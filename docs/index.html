Abstract

DOSELLOの標準初期局面について、双方が最善を尽くすと先手・黒が最終石差 +2 で勝つことを、独自Rustエンジンによる分散negamax探索で求めた。最善初手は f3-f4 と、その180°回転対称である c5-c6。758局面からなる証明木には456件の終局探索ジョブ結果を保存し、合法手と区間伝播を再検査した。本稿の「解決」は標準初期局面のゲーム理論値を意味し、全到達局面を解いた主張ではない。

We report a solution of the standard initial position of DOSELLO, a domino-placement Othello variant. With perfect play, Black wins by two discs. The optimal opening moves are f3-f4 and its 180-degree rotational counterpart c5-c6. A distributed best-first negamax proof combines exact searches with null-window bound searches. Its saved certificate contains 758 positions and 456 completed jobs, totaling 6.736 trillion searched nodes. We release an independent engine, the sanitized proof archive, a consistency checker, and a self-designed WebAssembly demo. The checker validates legal transitions and interval propagation; it trusts saved solver results and does not independently re-solve the leaves.

Initial value: Black +2

1. Introduction

原作 DOSELLO — オセロのアレンジゲーム は第三者の作品である。本研究はそのルールを独立に実装した。原作のJavaScript、HTML、CSS、画像・faviconはこのリポジトリに含めていない。

盤は8×8。初期配置は黒白各4石、計4個のドミノからなる。各手で縦または横に接する空き2マスへ同色のドミノを置く。通常のオセロと同様に8方向の直線で相手石を挟み、直接捕獲した石のドミノ相方も同時に返す。この相方反転から新たな捕獲は連鎖しない。少なくとも1石を直接挟む着手が合法となる。

合法手がなければパスし、双方が打てなければ終了する。得点は盤上の黒石数−白石数で、残った空きマスは勝者に加算しない。石の色だけでなく、どの2マスが相方かという情報も局面の一部である。

2. Game size & comparison with Othello

初期空きは56マスで、1着手につき2マス埋まるため最大28着手（パスは数えない）。Rustの独自合法手生成で、各局面の合法手を一様に選ぶ固定シードの100,000局を再計測した。平均は24.86827着手だった。序盤の平均分岐数は20.00, 12.70, 14.33, 13.13, 15.07, 14.98, 14.99, 15.28, 14.61, 14.92, 13.86, 13.98, 12.75。

3. Engine

標準ライブラリのみを使うRustエンジンを構築した。黒石・白石・横ドミノ左端・縦ドミノ上端の64ビット盤面と手番を局面キーとし、2マス配置の生成、方向別挟み判定、相方反転をビット演算で処理する。JavaScriptにも独立したルール実装を用意し、WASM出力と照合できる。

中盤は反復深化とPVS、16バイトの置換表エントリ、学習したパターン評価、ProbCutで探索する。終盤の証明では選択的探索の値をそのまま証明値にせず、完全探索の上下限へ分離する。評価学習は448,714レコード（対称重複除去後338,899局面、完全教師97,552局面）を用いた。完全教師holdout 9,983局面のMAEは19.93から11.17石へ改善した。学習データ全体と訓練ジャーナルは本公開セットには含めず、推論用の重みを同梱する。

並列化はYoung Brothers Wait Concept (YBWC) に基づき、最初の兄弟を先に探索してから残りを並列処理する。既存測定で14スレッド時に約3.7–3.8倍の高速化を得たが、負荷・局面依存である。Apple M4の単一スレッド完全探索の代表局面では約10.6M nodes/sを記録した。これらは先行ベンチマークの報告値で、今回の証明計算の平均速度ではない。

同じRustソースを wasm32-unknown-unknown 向けにビルドし、ブラウザではWorker内で解析する。共有メモリや特別なHTTPヘッダは不要。約5.6 MBの小型定石だけを読み込み、大規模分割ブックは配布しない。デモは証明済みの値・境界と時間制限付き推定を区別して表示する。

4. Proof method

局面の手番側価値Vに対し、negamax関係 V(s) = maxm −V(s·m) を利用する。子の区間が[Li, Ui]なら親へ [max(−Ui), max(−Li)] を伝播できる。最有望手の値を完全求解し、他の手はそれを上回れないことをnull-windowの境界探索で示す。全手の厳密な値を求める必要はない。

coordinatorはbest-firstで証明を進め、空いた計算枠では候補を投機的に処理する。長い仕事は子局面へ分割する。今回の保存証明では初期局面から3着手先、50空きで全ジョブを実行した。対称局面をまとめ、得られた境界を共有して上位へ戻す。

coordinatorは探索を担当せず、SSH先のworkerが実行する。チェックポイント・原子的な状態保存・ジョブ識別子・再試行により中断から再開できる。復旧経路と失敗注入は小規模なローカルテストで確認する。公開ホスト設定は host-a/b/c の例のみであり、本稿の作成中にSSHや分散計算を起動していない。

7. Verification & limitations

proof/verify.py はRustの job --type inspect で各局面の全合法手を取得し、保存された全子局面・対称手の対応を比較する。ジョブ結果の局面ID、型、閾値、区間を検査し、終端値と保存ジョブの区間だけからnegamaxを反復して全局面の区間を再構成する。初期[2,2]、2つの最善初手、返信表、PV先頭3手を検査する。

検証の限界：保存された葉の完全探索結果は本エンジンの出力を信頼する。ここでは葉を独立に再求解していない。合法手生成の検査も同じRustルール実装を利用しており、異なる第三者実装による独立証明ではない。証明木には未探索区間[−64,64]の葉が374個残るが、それらが根の区間を変えないことは区間伝播で検査する。

生のジョブ結果は proof/initial-proof.json に含める。プライバシー保護のためホスト名のみ汎用名へ置き換えたため、元ファイルとはSHA-256が異なる。局面ID・区間・探索ノード数・時刻は保持する。検査報告には公開ファイルのハッシュを記録する。全探索の訪問局面列、巨大な定石ジャーナル、学習用全データは含まない。

推定値を用いるデモは常に完全プレイを保証するものではない。定石の外では時間制限付きの探索になる。ゲーム規模の外挿や機種間の速度比較も別の実験条件に依存する。

8. Strength vs the original site CPU

提供された対戦成績は、原作最強CPU（レベル5）に対し200局で194勝・0分・6敗。条件は500ms/手、最初の4着手をランダム化、色を入れ替えるペア対局、定石なし。この500ms実験の生ファイルは公開準備時の資料から確認できていないため、保存済み実験と分けて掲載する。

保存資料で直接確認できた別実験は100ms/手、200局で191勝・1分・8敗。保存出力を同梱する。相手は原作CPU互換の固定深さ方式で、両者に同一計算時間を与える比較ではない。今回のオフライン準備中にこれらの対戦を再実行していない。勝率は初期局面の解決を証明する根拠でもない。

Reproducibility

リポジトリのルートで実行する。Rust、Python 3、Node.js 22以降を用意する。Rust外部crateやnpm依存はない。

export CARGO_TARGET_DIR="$PWD/rust/target"
cargo build --release --offline --manifest-path rust/Cargo.toml
cargo test --release --offline --manifest-path rust/Cargo.toml
DOSELLO_OFFLINE=1 npm test
python3 proof/verify.py
rust/target/release/game_stats 100000 5
python3 proof/summarize.py
python3 -m http.server 8000 --directory docs

ブラウザで http://localhost:8000/ と /play/ を開く。WASMを再生成する場合は、インストール済みの wasm32-unknown-unknown ターゲットで bash rust/tools/build-wasm.sh を実行する。公開予定URLは wand125.github.io/dosello/。この成果物はローカル準備のみで、GitHubへの作成・push・Pages公開は行っていない。

任意の原作照合は、ネットワークを許可する利用者が DOSELLO_OFFLINE=0 bash rust/tools/crosscheck.sh を明示的に実行する。原作コードは実行時に無視対象のキャッシュへ取得し、入手できなければSKIPする。分散計算の手順と汎用ホスト設定はREADMEを参照。
